Repository and architecture

Start with main.lua for host behavior, an existing panel for presentation, or a service for data acquisition. AeroGrid runs as one EdgeTX widget; the dashboard's panels are modules managed by that widget, not separate EdgeTX widgets.

The project specification provides design background. Check the implementation and its tests for exact current signatures; planning examples can describe earlier contracts.

Follow a dashboard from disk to display

  1. EdgeTX loads main.lua and passes a zone and the native Layout and Theme options. Layout choices use stable positions maintained by layout_registry.lua. Stable layout positions are stored in /AEROGRID/layout-registry.txt, separately from /AEROGRID/theme-registry.txt.
  2. The host resolves the selected name through layout_store.lua. A saved /AEROGRID/layouts/<name>.yaml takes precedence over the bundled /WIDGETS/AeroGrid/layouts/<name>.yaml; a missing file can fall back to Default.
  3. yaml.lua tokenizes the constrained YAML format; layout.lua validates version, grid, placements, and configuration. grid.lua turns zero-based positions and spans in the 4 x 4 grid into pixel rectangles.
  4. The host loads services and panel modules, checks compatibility, resolves typed settings, and creates each panel inside its own LVGL container.
  5. Foreground/background callbacks update subscribed services and dispatch panel work. A zone or fullscreen change triggers bounded reflow rather than reconstructing every object in a single frame.

Host coordination has three boundaries:

Module Ownership
dashboard_loader.lua Layout recovery, staged parsing, service/panel construction, and placement-local services.
dashboard_lifecycle.lua Empty-page decoration, batched reflow, fullscreen-to-App rebuilds, and page retirement/replacement.
editor_controller.lua Editor activation, staged advancement, dashboard previews, draft restoration, and adoption after saving.

Their new functions bind host operations once per widget. They do not capture another widget's context or introduce per-refresh forwarding wrappers. main.lua decides which operation advances; loading and cleanup keep their explicit stages. Page retirement and replacement run in separate callbacks so deferred cleanup cannot invalidate objects belonging to the replacement page.

Panels use container-local coordinates. They must not draw at absolute screen coordinates or assume the TX16S's dimensions. The host reserves the same top-left footprint for the native App-mode menu and fullscreen AeroGrid menu. Use the shared geometry instead of adding panel-specific menu offsets.

lib/package.lua records package, runtime API, panel API, and layout versions. The current layout schema is version 5. The central layout module keeps an adjacent migration registry: each source version provides a header step and a panel step for that version-to-next-version transition. A future version must add every intervening step; a layout is rejected if its source version is newer or any transition is missing.

Runtime loading validates the header, applies at most one header transition per loader callback, then parses each panel and applies at most one panel transition per callback before validating and building that panel. Staged Save follows the same bounded progression, keeping header migration, each panel migration, validation, and persistence in separate callbacks. The synchronous whole-layout helpers are for tests and tools, not runtime callback paths. Loading changes only the in-memory document and emits an upgrade notice; only explicit editor Save persists the current schema. Runtime modules expose RUNTIME_API; panels expose apiVersion. The host surfaces incompatible modules and isolates failures where possible. These checks detect incompatible mixtures, not every stale or mixed package: deploy the complete widget directory.

Shared services own firmware reads

Panels subscribe in create, retain read-only snapshots, and render them. They do not each poll EdgeTX or maintain their own telemetry cache. Subscriptions to the same source share polling, and an unsubscribed service does not consume scheduled work.

Service module Responsibility
telemetry_service.lua Source resolution, readings, units, precision, freshness, and link status.
model_service.lua Model identity/image, timers, flight mode, and TX voltage.
control_service.lua Trims, final channel outputs and their trim associations, switch conditions, GV snapshots, and verified GV9 FM0 increments.
armed_service.lua Saved model Armed precedence, legacy switch fallback, and immutable effective arm views over shared Control polls.
flight_service.lua Shared model-flight detection, once-only count, optional Sticky output, and timestamped boundaries.
smart_flight.lua Optional protocol-identified flight sensors with per-sensor receipt/freshness and SI units.
extrema_service.lua Sensor extrema and dashboard flight-session tracking.
navigation_service.lua GPS fix, pilot/home position, distance, and north-up bearing.
history_service.lua Error-bounded chart recordings, cumulative recording time, flight boundaries, raw extrema, line-only smoothing, and bounded rolling expiration.
services.lua Environment/snapshots, subscription registration, and bounded scheduling/update dispatch.

Snapshots are read-only views over service-owned state, mutated in place by the service to avoid per-frame allocations. Missing APIs, unknown sources, and missing fixes yield unavailable data; panel code must handle that explicitly.

services.addSubscription publishes an entry's live view and records its polling order/count. Each domain service still owns name lookup, duplicate detection, source resolution, and its polling metadata. Link/session-only subscriptions remain separate from source polling lists.

Telemetry zero is not inherently unavailable. EdgeTX can return zero both for a real reading and for a stopped stream. AeroGrid preserves the last live value when an ambiguous zero arrives with a down link, but accepts a live zero. getRSSI() is not reliable for every protocol; the service can stop trusting it when a non-zero source proves that telemetry is arriving. Staleness is link-wide, not per sensor, and a configured but never-received sensor can appear as valid zero on a live link. Local switch values remain usable without a receiver.

Chart history observes completed telemetry polls rather than reading changed revisions during redraw: unchanged numeric samples still occupy recording time, and raw spikes must not be lost between frames. Observer failures are isolated from telemetry polling and reported through normal service failure handling. services.armed:state() describes the saved model condition; :state(legacySwitch) resolves model-over-legacy precedence for a consumer. Snapshots expose condition, key, origin, generation, configured, available, fresh, updatedAt, Boolean value, revision, and status. An unavailable/stale reading is not disarmed. Reliability is evaluated on access with a one-second maximum sample age, so a failed poller cannot leave a permanently fresh reading. revision changes on observed sample/reliability changes; generation changes when the widget runtime is rebuilt. status is unconfigured, ready, or unavailable; invalid configuration is reported through normal host error isolation. The resolver owns no separate polling work: Control still reads each switch once per runtime. Configuration is model-wide; each dashboard publishes its own view over that same condition.

History and extrema key sessions by the effective condition. A configured model Armed unifies their arm inputs; absent model arming retains independent legacy switches. Each chart arm configuration has its own cumulative session. It pauses on disarm unless a matching shared flight is still active, including its disarm grace, and resumes the same recording; geometry reflow keeps it, while rebuilding the service runtime clears it. Each source/options subscription stores at most 6,144 connected linear knots. A fixed-anchor slope corridor chooses synthesized shared endpoints within half a displayed precision step of every observed value (filtered values if EMA is enabled). Numerical margin is reserved before accepting a segment; when that margin consumes the tolerance, exact native values are retained. Unknown sensor precision uses the strictest supported tolerance until discovery completes.

Knots use chunked <I4n / <I4j packing: cumulative recording ticks with gap/type bits and a lossless native Lua float or integer. Payload is 48 KiB per full recording on float32 firmware, or 72 KiB on double-precision hosts, excluding string/table/index and rendering overhead. Matching armed-switch/source/options subscriptions share storage. Absolute first/last sequence IDs and scalar history:point reads avoid per-knot snapshot tables. Growing history freezes at capacity without relaxing accuracy; rolling expiration reuses ring slots while retaining an interpolation anchor. Raw readouts/extrema continue even when plot storage is full.

Multilevel extrema/gap indexes accelerate projection only inside one pixel column; they never replace stored knots. Projection, native trace updates and gap-marker updates are staged with bounded work per callback. Geometry changes restart pending projection. Recorded gaps stay separate except when their endpoints coincide on screen; marker objects are pooled by pixel column. Unchanged readouts are cached so their callback budget can process a larger bounded projection batch; same-pixel extrema do not add redundant geometry.

History consumes at most one flight journal record per service turn, keyed by the event's pinned armKey, never by the optional Sticky output or the current broker arm. Per effective arm, 128 recording spans map wall-clock at timestamps to the cumulative recording axis; qualification/confirmation receipt times do not place boundaries. Grace samples remain after the mapped end. A 64-interval ring supplies scalar history:flight(sessionView, index) reads, independent of metric subscriptions. Shaded flight bands are staged in a bounded native-object pool behind the grid and traces. Each chart snapshots its inputs and stages a complete plot in a second reusable buffer before swapping it on screen. Arm/disarm triangles use a bounded directional transition journal. A separate resume journal drives fixed-width axis gaps and dotted trace connectors; the same projection maps traces, flight bands, grid lines, and axis markers. Crowded gaps evict the oldest visible section rather than narrowing the gaps. During normal sampling, flight bands clip to the recorded telemetry horizon. Telemetry-sampling turns reserve projection headroom without lowering the existing callback or staged-drain limits.

Journal loss sets the session's flightLost flag and closes an unmatched open band at its last observed recording time rather than extending it into later flights. Late attachment can recover the current active interval only from its recorded portion; old completed flights do not create new history. Model epochs clear intervals and mapping spans. Draft chart previews read compatible live views through a read-only facade and make no live subscriptions. Compatible previews can become live panels after saving without losing history; new or incompatible subscriptions require a post-save rebuild.

Shared flight tracking

The factory-scoped broker in flight_service.lua owns a separate non-UI Control/Telemetry runtime and optional Smart sensor poller. Any live widget callback can pump it. Dashboard registrations are weakly held; rebuilds mark proposals pending before replacing them. Unanimous effective arm/configuration proposals are required, not the first caller's settings. Saved model Armed overrides every declaration. A qualified session pins its arm, detector settings, and output until completion, including output cleanup when proposals change or conflict. Counter panels only render state.

services.flight:state() is an immutable live view. It exposes model/epoch, configuration revision/status, phase (ground, starting, active, ending), active, flight ID/count, candidate/qualification/disarm/completion timestamps, qualification reason and smartStatus, and actionable diagnostics. ready describes configuration, not telemetry validity. Unknown/stale arm observations never confirm disarm.

services.flight:boundaries(afterSequence, epoch) returns immutable records, the oldest retained sequence, and a gap flag. The journal retains 64 start/end records with epoch, sequence, flight ID/count, pinned armKey, kind, at, observedAt, and qualification reason (standard, smart-altitude, or smart-speed). Start at is the motor candidate start; end at is the final disarm start. observedAt is qualification or completion, so duration excludes the disarm grace. Consumers must reconcile a gap or changed epoch; they must never read Sticky output as their event bus. Smart shortcuts use the same qualification/effect path; they do not move the candidate timestamp. The standard timer remains an independent OR path.

Model flight.smartDetection defaults false. Smart requires EdgeTX getSourceValue receipt/current/fresh flags, not getValue zeros or link-wide freshness. Firmware isFresh spans roughly 160-320 ms; isCurrent only means the sensor is not marked old and may remain true for seconds after updates stop. Numeric receipt timestamps are not exposed. Smart bridges current finite readings for at most 1.2 seconds after positive per-sensor isFresh evidence; polling a cached value never renews that evidence. Never-received, old, unavailable, invalid, or expired data invalidate immediately. A shortcut can finish only once renewed evidence from every required source spans the full two-second hold; a cached value alone cannot finish it. Continuity counters preserve invalidations between detector ticks. This supports healthy 500ms/1s streams without treating the short fresh flag as a minimum update rate. Receipt age remains bounded evidence, not an exact timestamp or instant stopped-stream detector. Callbacks too infrequent to observe fresh flags conservatively fall back to standard detection.

The Smart poller is due every 100ms. Ordinary chart callbacks continue on Smart polling callbacks: the host reduces that callback's dashboard telemetry batch from eight sources to four, reserving room for Smart's four sensor categories. Both pollers retain round-robin progress; Smart does not skip whole chart callbacks. Selected metadata is compared directly rather than rebuilding identity strings on every poll. Expensive loading/editor work still gets separate, per-widget fair slices, and pending input takes priority. Discovery uses numeric telemN sources and custom sensor metadata from model.getSensor, never names or units alone. Supported single-module families are CRSF (including ELRS) and native FrSky S.Port; unknown/MULTI or multiple active modules fall back rather than guessing. CRSF barometric altitude is ID 0x09/instance 0; GPS position, groundspeed, and satellite count are ID 0x02/instances 0, 2, and 5. S.Port uses the firmware barometric/GPS position/groundspeed ID ranges, with matching GPS/speed instances. Calculated sensors and GPS altitude are excluded. Ambiguous categories are disabled independently. GPS requires fresh valid coordinates/delay and, on CRSF, at least four fresh satellites. Numeric inputs reject nonfinite values and normalize metres/feet and knots/m/s/ft/s/km/h/mph.

Altitude references require an observed disarmed-to-armed transition using a recent sample explicitly witnessed while disarmed, or fresh evidence at that transition. Merely current late readings never rebase an armed session. Motor interruptions preserve the reference but reset holds; unknown arm resets holds without inventing disarm. Metadata changes and scheduling gaps invalidate the reference conservatively. Fixed shortcuts are strictly above +3 m or 10 mph for at least 200 ticks, allowing only precision-scaled conversion roundoff (including float32 firmware). smartStatus explains fallback in the native Model settings dialog; confirmed field changes persist and update live detection immediately.

Model settings use their own schema/revision and losslessly encoded model filename under /AEROGRID/models/. Saves verify model identity and revision before verified file replacement. Layout saves and previews never write this document. Legacy detector declarations remain compatible until model settings are changed; retained arm metadata stays with its layout rather than becoming model-wide Armed. Schema version 1 has an optional top-level armed condition: missing preserves per-consumer legacy fallback, while "" explicitly disables arming, including fallbacks. Nonempty values must be physical positions or logical switches L01–L64 (optionally inverted). Numeric channel IDs are rejected. The model document is loaded in a separate callback before Armed and panel construction. Saving a different arm condition rebuilds every registered dashboard and clears captured homes, preserving layout data and a pinned active flight's completion/cleanup. Previous per-widget Armed selections are never silently promoted; conflicting old selections require an explicit model choice. The optional top-level sessionReset uses the same switch syntax; missing or "" disables it. A shared control poller detects false-to-true transitions independently of flight detection. Activation advances the flight epoch, cancels detection, releases its owned output, and resets each dashboard's session data in bounded service/panel callbacks. Subscriptions, screen objects, and editor drafts stay intact; charts reuse their plot buffers. Counting waits for a fresh disarm observation. Model changes also reset the flight epoch; ordinary dashboard rebuilds do not.

Add or change a panel

Use panels/flight-mode.lua as a small working example and lib/panel_host.lua as the authoritative contract.

Declaration or callback Role
id, apiVersion, supportedSpans Identify the module, check compatibility, and advertise valid grid sizes.
settings Typed fields, defaults, bounds, and choices used by validation and the editor.
refreshInterval Desired foreground interval in 10 ms ticks; work still shares the host budget.
refreshCost Whole-number share of the six host refresh slots (default 1). Chart uses all six so dense layouts cannot batch expensive redraws into one callback.
create(parent, rect, settings, services) Build LVGL objects, subscribe to data, and return private instance state.
refresh(context) Optional callback to update existing objects from snapshots. May return a whole-number interval of 1–6000 ticks; nil preserves the current interval. A second result of true reserves subsequent turns among panels of the same type until the update completes; other panel types and services continue running.
update(context, rect, settings, detailsOnly, placement) Optional geometry/configuration update. Host reflows and editor resizes pass the current grid placement as the fifth argument, leaving the internal detailsOnly argument unset.
background(context) Optional work when the dashboard is not visible.
resetSession(context, now) Optional session-data reset without rebuilding the panel. A second result of true requests another bounded reset turn.
event(context, event) Optional event handling; return true when consumed.
destroy(context) Optional cleanup of panel-owned references.
validateSettings(settings, span, config) Optional cross-field and span-dependent validation.

Put the module at panels/<type>.lua and reference that type in a layout. Regular panels declare supportedSpans = { "any" } and adapt their contents to every in-bounds span of the 4 x 4 grid. Use an explicit span list when there is a real rendering constraint: Host diagnostics and Service probe need at least 2x2, Chart needs a wide or square placement at least 2x1, while Theme showcase requires 4x4. Declare only spans you actually render correctly. A list setting (type = "table") declares entry fields with keys or nested paths, labels, types, and appropriate defaults/bounds/choices. The editor uses this schema to offer even fields omitted from the YAML, and can remove cleared optional fields. List declarations, including nested lists, can set itemLabel to a singular name such as "Metric" or "State". The editor names rows using the first nonempty label or source, then itemLabel and the one-based index; lists without itemLabel use "Entry". Do not build a separate settings UI for each panel.

The public theme.lua API composes palette/state resolution with typography.lua (measurement, font fitting, unit metrics) and panel_layout.lua (frames, slots, bands, and regions). The public primitives.lua API composes LVGL objects with reading.lua (reading/unit composition, redraw detection, and visibility/reflow reconciliation). Installed functions are direct references, not per-call wrappers; each widget has its own caches and mutable API tables.

The host supplies these dependencies when executing the modules. Pure-Lua tests use tests/support/module_loader.lua to compose the same APIs without installing firmware globals.

Use theme.lua for bands, font fitting, shared colors, and spacing, and primitives.lua for reusable LVGL objects. primitives.reading constructs the matching value/unit arrangement used by the battery and link readouts; optional units and differing initial geometry remain panel-specific. Keep a reading's font stable as its value changes, using the widest expected representation to choose it. When changing settings vocabulary or rendering, inspect sibling panels so the same setting retains the same meaning.

Add focused tests, an integration case at every declared span, a simulator review layout when useful, and a panel reference page. If adding screenshot support, add a capture recipe and adapter as described in Project tools.

Editor and persistence

editor.lua owns draft operations; editor_ui.lua and editor_drawer.lua present them; editor_controller.lua coordinates them with the live dashboard. layout_store.lua handles saving, backups, and user-versus-shipped resolution; layout_registry.lua maintains name-to-choice positions. Keep these boundaries intact when changing save behavior. Panel settings drawers, including entry subdrawers, put Label first when declared, preserving the declaration order of all remaining controls.

Editing does not overwrite bundled layouts. Save writes to /AEROGRID/layouts/, and Save As creates a named user layout. The layout registry is initialized at script load, so new names require a restart before appearing in the native Layout picker. Save errors must preserve the draft and report failure. Test persistence through the store/editor suites, not just the visible dialog.

Firmware constraints that affect design

EdgeTX limits a widget callback to 20,000 Lua VM instructions. Creation, parsing, panel building, reload, and reflow are staged across callbacks. Services have bounded subscription updates, and panel work is capped and phase-staggered. Do not replace this with one synchronous "simpler" loader. The budget tests require strictly less than 75% of the callback allowance.

Avoid object churn and retained callbacks. Shared labels install a persistent font callback; change its backing state through primitives.setFont rather than replacing the callback during refresh/reflow. Replacement retained Lua registry references in EdgeTX 2.12.4.

Other firmware details already have helpers and regression coverage: theme.measureText uses lcd.sizeText where available and estimates otherwise; trim sources do not identify their axis, image decode failure is not reported by lvgl.image, and lvgl.arc positions use the center rather than the bounding-box corner. Reuse the existing panel logic, file checks, and primitives.arcBounds instead of introducing alternate assumptions.
